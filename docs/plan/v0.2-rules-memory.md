# LazyTrae v0.2 — Project Constitution, Rules, and Memory

> **Version 0 build.** Part of the v0.x series.

Install the behavioral foundation.

## Deliverables

- `AGENTS.md`
- `.trae/rules/lazytrae.md`

## Rules to Encode

- Inspect before editing.
- Plan before multi-file or risky changes.
- Preserve canonical historical source record semantics unless deviation is documented.
- Execute one checklist item at a time during start-work.
- Verification evidence is required before completion.
- Reviewer/Oracle review is required for long-horizon completion.
- Update memory after accepted changes.
- Never claim parity without evidence.

## Verification

- Confirm every canonical method is in the command index or explicitly deferred.
- Confirm rules do not contradict historical source record source docs.
- Run existing repo tests/checks if present.

## Success Criteria

A Trae agent opening the repo immediately understands LazyTrae's operating contract.

## Rollback

Remove managed LazyTrae blocks from AGENTS.md and delete `.trae/rules/lazytrae.md`.

## Verification Notes

### historical source record rules component (verified from source)

The `rules` component at `plugins/workflow/components/rules/` implements:
- **Static injection**: loads AGENTS.md, `.codex/rules/`, rule files at SessionStart and UserPromptSubmit
- **Dynamic injection**: after PostToolUse, extracts file paths from tool input, fingerprints them, loads relevant rules
- **Context pressure handling**: skips injection when transcripts contain compaction markers
- **Post-compact recovery**: tracks compacted state for correct re-injection

### Trae Rules (verified from docs.trae.cn/ide_rules)

- Project rules in `.trae/rules/` directory
- Markdown format
- Only active in the configured project
- Can specify code style, language/framework, API constraints, architecture rules

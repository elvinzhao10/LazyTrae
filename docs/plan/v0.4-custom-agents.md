## Role Boundaries

| Role | Mission |
| --- | --- |
| Sisyphus | Main orchestrator. Decides whether to plan, execute, review, or loop. |
| Prometheus | Planner only. Interviews, writes plans, no product-code edits. |
| Metis | Pre-planning risk analyst. Finds hidden requirements and ambiguity. |
| Momus | Plan reviewer. Rejects vague, untestable, or unsafe plans. |
| Atlas | Executes approved checklist items one at a time. |
| Hephaestus | Deep autonomous worker for hard implementation/debugging. |
| Oracle | Reviewer/architecture/debugging consultant. Prefer read-only. |
| Librarian | Maintains project memory, docs, command index, parity ledger. |
| Explorer | Fast codebase scout. Read-only search and path mapping. |
| Cleaner | Removes AI-slop while preserving behavior. |
| Migration Planner | Converts LazyCodex methods to other hosts. |

## Verification

- Every role has mission, allowed actions, forbidden actions, required context, handoff format, and verification responsibility.
- No two agents have conflicting authority.
- Orchestration diagram covers init-deep -> plan -> implement -> verify -> review -> librarian update -> loop.

## Success Criteria

A Trae user can configure or invoke specialized LazyTrae agents from the generated Markdown definitions.

## Rollback

## Verification Notes

### LazyCodex agent roles (verified from source repo)

TOML agent role files in `plugins/omo/components/ultrawork/agents/`:
- `explorer.toml` — internal codebase context
- `librarian.toml` — external docs, library contracts
- `plan.toml` — plan drafting and task decomposition
- `momus.toml` — missing decisions, edge cases
- `metis.toml` — risk review

Additional roles from `docs/discipline-agents.md`:
- `lazycodex-executor` — executing task units from a plan
- `lazycodex-code-reviewer` — post-implementation code quality review
- `lazycodex-qa-executor` — real-execution-based QA
- `lazycodex-gate-reviewer` — pre-completion verification gates
- `lazycodex-clone-fidelity-reviewer` — clone and sync fidelity checks

Key principle: "completion judgment is never handed wholesale to a sub-agent. The parent session keeps ownership of goals, constraints, and final judgment."

### Trae custom agents (verified from docs.trae.cn/ide_agent)

- Create via UI or config
- Fields: name, prompt, MCP servers, built-in tools (read, file system, terminal, web search, preview)
- "Can be called by other agents" toggle with English identifier and "when to call" description
- Only the built-in "Agent" can call custom agents (subagent pattern)
- Agents have independent context when called

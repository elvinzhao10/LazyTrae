# LazyTrae v0.0 — Product Overview

> **Version 0 build.** All version numbers use the `v0.x` scheme.

## Product Definition

LazyTrae is a Trae-native recreation of LazyCodex/OmO workflows.

It should let a Trae user do this:

1. Open a repo in Trae.
2. Run or paste /init-deep.
3. Ask for a complex task with ulw / ultrawork.
4. Or use /ulw-plan for precise planning.
5. Use /start-work to execute the approved plan.
6. Use /ulw-loop for long-horizon "continue until verified" work.
7. Get verification, review, evidence, handoff, and memory updates.

It should not depend on the original LazyCodex runtime after installation.

## Design Principle

LazyTrae = LazyCodex/OmO semantics + Trae-native UX + optional local runtime.

LazyCodex should be treated as the semantic source of truth, but Trae should not try to mimic Codex/OpenCode internals one-for-one. Public OmO/LazyCodex docs describe OmO as a multi-agent orchestration harness with Sisyphus, Prometheus, Atlas, Oracle, Librarian, Explore, category routing, ultrawork, /init-deep, /start-work, /ralph-loop, /ulw-loop, /handoff, /remove-ai-slops, Team Mode, MCPs, hooks, and durable .omo state. The LazyCodex/Codex Light edition is explicitly a thin Codex-platform distribution over omo-codex, with components like rules, comment-checker, git-bash, lsp, ultrawork, ulw-loop, start-work-continuation, teammode, and telemetry wired to Codex lifecycle events.

Trae gives enough native surface to recreate the experience differently: official docs expose custom agents with prompts/MCP/built-in tools, Skills & Commands through SKILL.md, user/project Rules, MCP, lifecycle hooks as shell commands, SOLO Agent for complex project workflows, Max mode for larger context/tool-heavy runs, and Markdown-defined subagents for SOLO auto-invocation.

## Implementation Strategy

Build three layers:

### Layer 1 — Trae-native interface

```
.trae/rules/
.trae/skills/*/SKILL.md
.trae/commands/
.trae/agents/
.trae/mcp.json
.trae/hooks/
```

### Layer 2 — LazyTrae project runtime

```
.lazytrae/state/
.lazytrae/plans/
.lazytrae/evidence/
.lazytrae/logs/
.lazytrae/schemas/
CLI: lazytrae init / doctor / sync / verify / handoff
```

### Layer 3 — OmO/LazyCodex compatibility

```
.omo/plans/
.omo/boulder.json
.omo/ulw-loop/
command aliases
parity ledger
```

Trae owns the user experience. LazyTrae owns durable state, evidence, verification, compatibility, and parity accounting.

## Functional Parity Map

| LazyCodex / OmO concept | LazyTrae equivalent | Implementation method | Parity target |
| --- | --- | --- | --- |
| ultrawork / ulw keyword | Trae command + skill trigger + prompt detector hook | .trae/skills/ulw-loop, .trae/hooks/user-prompt-submit.sh | High |
| /init-deep | Trae project memory bootstrap | Repo scanner + AGENTS.md + .trae/rules/lazytrae.md | High |
| /ulw-plan / Prometheus | LazyTrae Planner agent and skill | .trae/agents/prometheus.md, .trae/skills/ulw-plan/SKILL.md | High |
| /start-work / Atlas | Stateful plan executor | .lazytrae/state/boulder.json + Atlas agent | High |
| /ulw-loop / Ralph loop | Durable SOLO-style execution loop | .lazytrae/state/active-loop.json, .omo/ulw-loop/ mirror | Medium-high |
| /stop-continuation | Pause/cancel active loop | CLI + hook + state transition | High |
| /handoff | New-session continuation summary | lazytrae handoff + evidence file | High |
| review-work | Reviewer/Oracle protocol | Trae custom agent + SKILL.md | High |
| remove-ai-slops | Cleaner skill | SKILL.md + optional comment-checker script | High |
| Librarian | Memory updater | agent + skill + AGENTS/docs update protocol | High |
| Explore | Codebase scout | read-only custom agent/subagent | High |
| Metis/Momus | Plan critique roles | custom agents + plan review skill | High |
| Codex hooks | Trae lifecycle hooks | shell hook dispatcher where available | Medium-high |
| MCPs | Trae MCP config + LazyTrae MCP server | .trae/mcp.json | High |
| Model routing | Trae Auto/Max/custom-model guidance + optional runner | native hints; optional trae-agent backend | Medium |
| Team Mode | SOLO/subagents + optional file-backed team queue | .lazytrae/team/ later | Medium |
| Hashline edits | read-before-write guard, optional hash check | hook + CLI guard, not true native edit replacement | Medium-low |
| Codex marketplace install | not portable | replace with lazytrae init | Not applicable |

## Verification Against Official Documentation

### LazyCodex/OmO Source (verified from cloned repo)

- **LazyCodex** is a thin distribution layer over OmO (oh-my-openagent). Source: `README.md`, `packages/web/content/docs/overview.md`
- **Hephaestus** is the single discipline agent ported to Codex. No Sisyphus orchestrator in the Codex package. Source: `docs/discipline-agents.md`
- **Hooks lifecycle**: SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop/SubagentStop, PostCompact. Source: `docs/hooks-lifecycle.md`
- **Four core commands**: `$init-deep`, `$ulw-plan`, `$start-work`, `$ulw-loop`. Source: `docs/overview.md`
- **Boulder state** in `.omo/boulder.json` persists progress. Source: `docs/start-work.md`, `docs/discipline-agents.md`
- **Five evidence gates**: plan reread, automated verification, manual-QA, adversarial QA, cleanup. Source: `docs/hooks-lifecycle.md`
- **Model routing**: role-based profiles (default, plan mode, worker, verifier). Source: `docs/model-routing.md`
- **Components**: rules, comment-checker, git-bash, lsp, ultrawork, ulw-loop, start-work-continuation, teammode, telemetry, codegraph. Source: `plugins/omo/README.md`
- **Agent roles**: explorer, librarian, plan, momus, metis, lazycodex-executor, lazycodex-code-reviewer, lazycodex-qa-executor, lazycodex-gate-reviewer. Source: `docs/discipline-agents.md`
- **ulw-loop**: Self-referential loop, 500 iteration cap in ultrawork mode, Oracle verification required. Source: `docs/ulw-loop.md`
- **ulw-plan**: Prometheus planner, Socratic interview, parallel exploration, Metis gap analysis, Momus review. Source: `docs/ulw-plan.md`
- **init-deep**: Hierarchical AGENTS.md generation. Source: `docs/init-deep.md`

### Trae Official Docs (verified from docs.trae.cn)

- **Rules**: Project rules and global rules supported. `.trae/rules/` directory. Source: https://docs.trae.cn/ide_rules
- **Skills**: `SKILL.md` files, dynamic on-demand loading, structured format. Source: https://docs.trae.cn/ide_skills
- **Custom Agents**: Prompts + MCP + built-in tools (read, file system, terminal, web search, preview). Agents can be called by other agents. Source: https://docs.trae.cn/ide_agent
- **Hooks**: Six event types — SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, Notification. `hooks.json` config. Global and project hooks. Source: https://docs.trae.cn/ide_automate-actions-with-hooks
- **MCP**: Supported in TRAE IDE. `.trae/mcp.json`. Source: https://docs.trae.cn/ide_model-context-protocol
- **SOLO Mode**: TRAE Work (formerly SOLO), subagents supported. Source: https://docs.trae.cn/ide_solo-mode
- **Slash Commands**: Supported. Source: https://docs.trae.cn/ide_slash-commands
- **Memory**: Supported. Source: https://docs.trae.cn/ide_memories
- **Subagents**: Supported, can be called by built-in Agent. Source: https://docs.trae.cn/ide_subagents

## MVP Recommendation

Start with this reduced MVP:

- v0.0 — canonical discovery
- v0.1 — architecture
- v0.2 — rules/memory
- v0.3 — skills/commands
- v0.4 — custom agents
- v0.5 — state machine
- v0.6 — CLI doctor/init

Do not start with Team Mode, model routing, or optional trae-agent integration. Those are valuable, but they are second-order. The core LazyCodex magic to recreate first is:

```
deep repo understanding
→ plan
→ execute one task at a time
→ verify
→ review
→ continue if incomplete
→ record evidence
→ handoff cleanly
```

That is the real LazyTrae spine.

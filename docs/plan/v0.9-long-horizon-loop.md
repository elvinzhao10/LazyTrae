# LazyTrae v0.9 — Long-Horizon Execution Loop

> **Version 0 build.** Part of the v0.x series.

## Objective

Implement the real LazyTrae equivalent of ulw-loop.

## Loop States

- idle
- initializing
- planning
- active
- verifying
- reviewing
- blocked
- paused
- complete
- cancelled

## Loop Behavior

1. Load project memory.
2. Expand user goal into completion promise.
3. Run init-deep if project memory is missing.
4. Generate or load plan.
5. Select next actionable task.
6. Implement one bounded unit.
7. Run verifier.
8. If verification fails, diagnose and retry or mark blocker.
9. Run reviewer/Oracle.
10. If review fails, re-enter active state with reviewer blockers.
11. Update Librarian/memory.
12. Check completion promise.
13. Continue until complete, blocked, paused, or max-iteration reached.

## Verification

- Simulate a loop on a documentation-only task.
- Produce checkpoints.
- Force a fake verification failure.
- Confirm loop does not complete.
- Fix failure.
- Confirm reviewer passes.
- Confirm completion file is written.

## Success Criteria

LazyTrae can run an auditable end-to-end workflow and resume after interruption.

## Rollback

Run `/stop-continuation` or set active-loop status to paused/cancelled through CLI.

## Verification Notes

### historical source record ulw-loop (verified from source repo)

- Self-referential development loop that runs until verified completion
- Agent emits `<promise>DONE</promise>` but that does NOT end the loop
- Oracle must verify the result first
- If verification fails: "Oracle verification failed. Continuing ULTRAWORK loop."
- Iteration cap: 500 in ultrawork mode, 100 in normal mode
- Progress is checkpointed, survives restarts
- Source: `docs/ulw-loop.md`, `plugins/workflow/components/ulw-loop/`

### ulw-loop state management (verified from source code)

- Plan stored as JSON with goals, success criteria, statuses
- Steering mutations: add_subgoal, reorder_pending, revise_pending_wording, split_subgoal, mark_blocked_superseded, revise_criterion, annotate_ledger
- Mutation lock via file-based locking
- Audit ledger with idempotency keys
- Five evidence gates: plan reread, automated verification, manual-QA, adversarial QA, cleanup
- Source: `plugins/workflow/components/ulw-loop/src/steering.ts`, `plan-crud.ts`, `runtime.ts`

# v1.2.0 migration guide — native host boundaries

v1.2.0 is a documentation and evidence-boundary migration. It does not grant
new host authority. Trae IDE, Trae Work, and Trae CLI remain independent hosts;
package readiness never promotes host readiness.

## Before changing a project

1. Use **Node.js LTS 20 or newer** and **Git**, bootstrap only from
   `https://github.com/elvinzhao10/LazyTrae.git`, and use the durable
   `node "<install-root>/LazyTrae/launcher.js"` route.
2. Run `lifecycle status` and inventory receipt-owned, modified, linked, and
   caller-owned assets. Preserve everything not proven receipt-owned.
3. Select exactly one host and one evidence mode. Do not reuse evidence from a
   different host, build, session, or worktree.

## Host-specific migration

| Host | Keep/update | Do not infer |
| --- | --- | --- |
| Trae IDE | Project `.trae/` assets and an optional bounded probe. | Asset generation or a probe does not prove discovery, hooks, or a connected MCP. |
| Trae Work | Choose `--client desktop|web|mobile` and `--execution local|cloud` explicitly. Only desktop/local may use a local skills directory, worktree, executable, or bounded probe. | Descriptor-only web/mobile/cloud profiles do not upload, log in, access an account, or run cloud work. |
| Trae CLI | Generate receipt-owned `.traecli/` candidates only when the project is selected. | Candidates are inert configuration; they are not discovery, registration, execution, package installation, or marketplace publication. |

For a CLI candidate, an invocation remains pending until an exact,
fingerprinted host probe proves the structured runner for the selected current
session and worktree. A probe is bounded and credential-free; it is not host
readiness.

## Evidence migration

Current writers emit v2 readiness and host-adapter records. Treat every v1
receipt as immutable historical compatibility input: do not rewrite it, use it
as an active writer, or let it promote a current host. The current host status
remains pending until current fingerprint-bound probe, registration, session,
MCP, and live-observation evidence all agree.

## Safe rollback and removal

Use plan-first offboard and inspect the exact receipt-owned plan before a
confirmed removal. Remove only unmodified generated `.traecli/` candidates or
desktop/local Work assets named by their receipts. Preserve modified files,
descriptor-only profiles, host registrations, host settings, and caller paths.
Remove a host registration manually through the selected build's documented UI
or settings flow, one approved action at a time. There is no universal host
CLI command.

Historical v1.0.3 release evidence remains byte-for-byte historical material.
It is neither a v1.1 current-state writer nor authority to remove a newer
asset.

## Fix Protocol

For each issue found:
1. Record: file, line, issue category, severity (blocker / major / minor)
2. Fix the issue (do not just document it)
3. Re-verify the fix (run the relevant command)
4. If the fix would break another constraint (e.g., splitting a file to meet 250 LOC), do the split
5. Record evidence: command run, output, exit code, files changed

## Output

Produce `docs/lazytrae-diagnostics-report.md` containing:
- Diagnostic categories 1-10 with check results (PASS/FAIL per item)
- Every issue found with severity and fix applied
- Final state: `lazytrae doctor` output
- Parity ledger final numbers
- Files changed in this version
- Remaining issues (if any cannot be fixed)

## Verification

1. `node packages/cli/src/index.js doctor` — 0 FAIL, all checks PASS (1 WARN acceptable for MCP server not running)
2. All source files ≤ 250 LOC
3. All hooks ≤ 100 LOC
4. Parity ledger and command index fully consistent
5. All CLI subcommands functional
6. All schemas validate their state files
7. All hooks run without syntax errors

## Success Criteria

The codebase is clean, consistent, and ready for v0.14 final release. No known blockers remain. Every diagnostic category passes. The diagnostics report documents what was found and fixed.

## Rollback

If a fix introduces a regression, revert the specific commit. Each fix should be atomic (one issue per commit where practical).
